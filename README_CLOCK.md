# Re-Node: timer and alarm control

Type a timer / alarm command (or press the Mic button: basic offline voice, see README_GUI.md) and Re-Node sets it on the phone's Clock app, 100% offline (no internet, no
cloud, no new pip packages: standard library only).

    set timer for 10 minutes        alarm at 7:30 am every weekday        cancel all alarms        stop timer

## How it works

Routing in `main.run_autonomous_agent` is now: flagship workflows (mirror / mail) -> **timer / alarm command** ->
known skills -> learned skills -> reactive LLM loop. The new step is one `if` that only fires when the parser
fully understands the sentence, so every old command (mirror, mail, wifi, bluetooth, flashlight, airplane,
quick settings, home, back, anything the LLM loop handles) is routed exactly as before.

| Layer | File | What it does |
|---|---|---|
| Parser | `clock_skill.py` | Pure Python. Words to numbers ("one hour thirty"), 12h/24h, "quarter past 7", noon/midnight, "in 45 minutes", weekdays/weekends/daily/named days, `called <label>`, validation. No LLM decides a number. |
| State | `clock_state.py` | What Re-Node itself has set (timers with start time, alarms with next ring). Thread-safe, saved to `logs/clock_state.json`. Drives the GUI countdown list. |
| Workflow | `clock_workflow.py` | 1) Android Clock intents over adb (`SET_TIMER`, `SET_ALARM`, `SHOW_*`, `DISMISS_*`, with `SKIP_UI`). 2) Verify on the phone. 3) If refused / ignored / unconfirmed: Clock-app UI automation with selector fallback chains. 4) If that fails: dump the visible UI to `logs/last_failure_ui.txt` and report the failure. |
| GUI | `gui_app/clock_panel.py` | "Timers & alarms" panel. Every button builds a normal command and runs it through the same path as typing it. |
| Brain | `brain/brain.py` | New `TIMER` / `ALARM` intents so the cognitive log narrates the plan like it does for mirror / mail. |

**Alarm "alarm at 6" (no am/pm)** means the next time the clock reads 6:00: at 22:58 that is 06:00 tomorrow; at
10:00 it is 18:00 today. The log and the GUI status line always say how it was read.
"alarm at 6 pm" when 6 pm has already passed means tomorrow. "alarm in 2 hours" is computed from the PC clock
and turned into an exact time, because Android alarms have minute precision.

Nothing is reported as done unless it was confirmed on the phone (next-alarm setting, the Clock app's alarm list,
or a running countdown on the Timer tab). If the phone shows nothing readable at all, the log says
`UNVERIFIED` instead of pretending.

## Run it (PowerShell, from the project folder)

    cd C:\Users\DELL\Desktop\renode_with_gui\renode
    python gui.py --demo              # rehearsal: simulated phone, real parser, no adb / Ollama needed
    python gui.py                     # live: your phone over USB
    python main.py "set timer for 5 minutes"      # terminal mode works too
    python -m pytest -q               # full test suite (243 tests; the 3 Tk tests skip if there is no display)
    python inspect_ui.py --packages                       # find the Clock app's package name
    python inspect_ui.py --package com.coloros.alarmclock --all    # inspect the Clock app's screens

If the auto-detected Clock app is wrong, set `CLOCK_PACKAGE=` in `.env` (see `.env.example`).
Candidates tried, in order: `com.coloros.alarmclock`, `com.oplus.alarmclock`, `com.sec.android.app.clockpackage`,
`com.android.deskclock`, `com.google.android.deskclock`.

## The Timers & alarms panel

- **Timer**: minutes / seconds boxes + Start, quick buttons 1 / 5 / 10 / 15 min, Stop all.
- **Running timers**: live countdown (updates every 0.5 s); each row has its own Stop, which stops only that timer.
- **Alarm**: hour : minute, AM / PM switch, optional label, Set. Each alarm in the list has Cancel.
- **Status line** under the panel shows how a command was understood *before* it runs ("Understood: Alarm for
  06:00 AM tomorrow - next occurrence") and updates live while you type in the command box. Impossible input
  ("alarm at 25:00", "timer 0 seconds") is explained and never sent to the phone.
- The run-history table and success statistics are gone, as requested; the space is used by this panel.
- The window is laid out to fit a 1366x768 laptop without scrolling (checked headlessly at 100% and 125% font
  scale; see Limitations about real Windows scaling).

## What the parser understands (examples, generated by running it; "now" = Tue 27 Oct 2026 22:58)

| You type | Parsed as |
|---|---|
| `set timer for 10 minutes` | `SET_TIMER` Timer for 10 min |
| `timer 5 min` | `SET_TIMER` Timer for 5 min |
| `start a 30 second timer` | `SET_TIMER` Timer for 30 sec |
| `set a timer for one hour thirty minutes` | `SET_TIMER` Timer for 1 hour 30 min |
| `timer for half an hour` | `SET_TIMER` Timer for 30 min |
| `set timer 2h30m` | `SET_TIMER` Timer for 2 hours 30 min |
| `set timer for 2 min called pasta` | `SET_TIMER` Timer for 2 min (pasta) |
| `stop timer` | `STOP_TIMER` Stop timer |
| `stop the 600 second timer` | `STOP_TIMER` Stop timer (10 min) |
| `show timers` | `SHOW_TIMERS` Show timers |
| `set alarm for 7:30 am` | `SET_ALARM` Alarm for 07:30 AM tomorrow |
| `alarm at 6` | `SET_ALARM` Alarm for 06:00 AM tomorrow _(no am/pm given: next occurrence)_ |
| `set alarm for 6 pm` | `SET_ALARM` Alarm for 06:00 PM tomorrow |
| `wake me up at 5:45` | `SET_ALARM` Alarm for 05:45 AM tomorrow _(no am/pm given: next occurrence)_ |
| `alarm at quarter past 7 pm` | `SET_ALARM` Alarm for 07:15 PM tomorrow |
| `alarm at noon` | `SET_ALARM` Alarm for 12:00 PM tomorrow |
| `alarm at 0730` | `SET_ALARM` Alarm for 07:30 AM tomorrow |
| `alarm at 6:30 am tomorrow called gym` | `SET_ALARM` Alarm for 06:30 AM tomorrow (gym) |
| `set alarm for 7 am every weekday` | `SET_ALARM` Alarm for 07:00 AM tomorrow, weekdays |
| `alarm at 9 am every saturday and sunday` | `SET_ALARM` Alarm for 09:00 AM Sat 31 Oct, weekends |
| `wake me up in 45 minutes` | `SET_ALARM` Alarm for 11:43 PM today |
| `cancel alarm` | `CANCEL_ALARM` Cancel the next alarm |
| `cancel all alarms` | `CANCEL_ALARM` Cancel all alarms |
| `delete the 7 am alarm` | `CANCEL_ALARM` Cancel alarm 07:00 AM |
| `show alarms` | `SHOW_ALARMS` Show alarms |
| `alarm at 25:00` | **refused**: 25:00 is not a valid time |
| `timer 0 seconds` | **refused**: A timer needs a duration longer than 0 seconds |
| `set timer` | **refused**: How long should the timer run? e.g. 'set timer for 10 minutes' |
| `timer 25 hours` | **refused**: Timers longer than 24 hours are not supported |
| `mirror` | *not a clock command: routed exactly as before* |
| `mail` | *not a clock command: routed exactly as before* |
| `turn on wifi` | *not a clock command: routed exactly as before* |
| `my alarm app keeps crashing` | *not a clock command: routed exactly as before* |
| `set the table` | *not a clock command: routed exactly as before* |

Weekdays are Monday=0..Sunday=6 inside Python; the intent path converts them to Android's Sunday=1..Saturday=7.

## Known limitations (read before the demo)

1. **Not tested on a real phone.** Everything was tested against a simulated Clock app (AOSP / Google Clock style) and
   a simulated phone. Realme RMX3085 / ColorOS 13 ships its own Clock app, which may ignore `SKIP_UI`, show a
   confirmation screen, or not honour `DISMISS_*`. The code detects that (it verifies instead of trusting the
   intent) and falls back to UI automation, but the UI selector chains are written for common layouts and may need
   one adjustment on ColorOS. If a command fails: open `logs/last_failure_ui.txt` (it lists every element on screen),
   or run `python inspect_ui.py --package <clock package> --all` on the failing screen, and adjust the chains at
   the top of the UI section in `clock_workflow.py`.
2. Labels and repeat days are applied only through the intent path. The UI fallback sets the time only and logs a warning.
3. "Cancel alarm" switches the alarm **off** (keeps it in the Clock app, disabled) rather than deleting it.
4. The countdown / alarm lists show what **Re-Node set**. A timer started by hand on the phone is not visible, and
   "stop the 5 minute timer" refuses (and says so) for a timer Re-Node does not know about. Plain "stop timer" clears every timer on the phone.
5. Pausing a timer is not possible through Android's Clock intents; "pause timer" is reported as unsupported.
6. Times are worked out with the **PC clock**; the phone is assumed to be on the same time zone.
7. Timers longer than 24 hours and alarm labels over 40 characters are refused / trimmed. Labels keep letters, digits and `_ . , : -` only.
8. Windows display scaling cannot be tested here. Layout was checked at 1366x768 with 100% and 125% font scale under X11.
   If your laptop is set to 150% scaling and something clips, set Windows scaling to 125% or maximise the window.
9. `logs/clock_state.json` is not in `.gitignore` (that file was left untouched).
